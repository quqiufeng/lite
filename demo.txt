lite —— 一个原生的 AI Agent，完全不一样的思路

一、Agent 的能力被低估和限制

1. Agent 的能力上限应该由大模型去决定；所有的规则、插件、规范，都是在限制能力。
2. 操作系统本身就具有相当的能力：Agent 能使用系统，还包括使用浏览器、操作接入的各种设备。
3. Agent 需要支持长时间工作，拥有记忆能力，可以自己重启，最好支持操作另外的 Agent 集群。
4. Agent 的交互方式应该支持多种：微信、桌面应用、网页端口、语音。
5. 优化过的前缀缓存设计，非常节省 token。

二、lite 做哪些不一样的功能

1. 原生应用，性能优化到位，代码只有主流规模的 1/20，速度快。
2. 支持大模型 API 动态开发插件增强能力，支持重启。
3. 支持记忆功能，历史消息不丢失，使用过程中按需要自动召回；记忆文件迁移到新环境，可以复活。
4. 没有上下文限制，采用滑动窗口动态上下文。
5. lite 可以看见自己，支持自动化功能和界面测试，可以动态摸索实现你的指令，比如操作微信。
6. 自带了代码搜索、性能监控、语音功能、文档卡片等有用插件。
7. 自我开发：它是自己的第一个项目。

三、软件生态和公司治理新变化

1. 现有软件的功能更新依赖上游的发布，不好升级和集成其他业务，交互方式也有限。
2. Agent 开发软件的成本随着 token 降价越来越低，软件变得随用随走。
3. 在大模型智能还没有到一定程度的情况下，用 Agent 重写软件风险很大；但做新系统集成已经逐渐成熟。
4. 把 Agent 的智能化用在交互端和智能化领域，现有的公司 IT 资产做兜底。
5. 基于 lite，可以把消耗的 token 沉淀为带记忆的公司智能化资产。

四、Agent 对大模型的重要性

1. Agent 是大模型的手和眼睛；lite 提供了自我进化迭代的机制，让大模型决定 lite 的能力上限。
2. 用模型训练模型，离不开稳定高效的 Agent：能长时间工作，不丢失过往经验。
3. 模型的在线学习、持续学习，需要一个开放的、没有限制的 Agent，让模型探索现实世界。
